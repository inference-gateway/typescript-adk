# AGENTS.md

The TypeScript Agent Development Kit (`@inference-gateway/adk`) - a Node.js library for building A2A-protocol agents for the [Inference Gateway](https://github.com/inference-gateway/inference-gateway). ESM-only, requires Node 24+ and pnpm 10.18.0 (pinned via `package.json#packageManager`). The public API is not yet stable. Sibling to the Go ADK - patterns here often mirror the Go implementation.

## Commands

Use pnpm, not npm or yarn - `pnpm-lock.yaml` is the lockfile of record.

- `pnpm install` - install from the lockfile (frozen-lockfile in CI)
- `pnpm build` - bundle with `tsup` into `dist/` (ESM only, ES2024 target, `.d.ts` included, uses `tsconfig.build.json` which excludes tests)
- `pnpm test` / `pnpm test:watch` / `pnpm test:coverage` - Vitest (v8 coverage)
- `pnpm lint` / `pnpm lint:fix` - ESLint (Prettier enforced as rules)
- `pnpm format` / `pnpm format:check` - Prettier write/check
- `pnpm typecheck` - `tsc --noEmit`
- `pnpm generate:types` / `pnpm generate:types:check` - regenerate/verify `src/types/generated/a2a.ts` against the pinned schema

Run one test: `pnpm vitest run tests/agent/card.test.ts`, or by name with `-t "applies overrides over JSON values"`. Before release work, mirror `prepublishOnly`: clean, lint, typecheck, test, build.

## Architecture

Public exports start at `src/index.ts` (barrel). Domain code lives in `src/agent/` (agent card, build metadata, task state machine), `src/server/`, `src/client/`, `src/llm/`, `src/auth/`, `src/storage/`, `src/artifacts/`, `src/mcp/`, `src/telemetry/`, `src/metrics/`, `src/logging/`, `src/tls/`, `src/testing/`. Tests mirror `src/` under `tests/**/*.test.ts`, and fixtures live in `tests/agent/fixtures/`. Each `examples/<name>/` is a standalone package in the pnpm workspace (`pnpm-workspace.yaml`).

## Generated A2A types

`src/types/generated/a2a.ts` is generated by `scripts/generate-a2a-types.ts` from the canonical JSON Schema in `inference-gateway/schemas`, pinned by release tag in `scripts/schemas-ref` (`SCHEMA_REF`). **Never hand-edit `src/types/generated/`.** ESLint and Prettier ignore it. The drift check in `pnpm test` (`tests/a2a-types.test.ts`) fetches the pinned schema and fails if the committed file disagrees with regeneration - it has a 30s timeout and fails offline by design, not as a flake. Schema bump: change `scripts/schemas-ref`, run `pnpm generate:types`, commit both.

The generator's `normalizeSchema` does two things before calling `json-schema-to-typescript` - preserve both if you change it, or the output becomes a wall of numbered duplicate types:

1. Hoist inline named enums to top-level definitions (otherwise `TaskState`, `TaskState1`, ...).
2. Strip sibling keys from `$ref` usages (otherwise `Struct1`, `Struct2`, ...).

## AgentCard loading

`loadAgentCardFromFile` / `loadAgentCardFromJSON` (`src/agent/card.ts`) run, in order: parse JSON, resolve `${VAR}` placeholders against `options.env` (defaults to `process.env`), shallow-merge `options.overrides` (overrides win), then `validateAgentCard`.

- A missing env var **throws `AgentCardLoadError`** rather than substituting an empty string. Tests assert this.
- `validateAgentCard` checks only the required fields (`name`, `description`, `version`, `protocolVersion`, `defaultInputModes`, `defaultOutputModes`, `capabilities`, `skills`). Optional fields stay loose by design so callers can compose partial cards.
- `loadAgentCardFromFile` is synchronous by design (`readFileSync`, boot-time config). Don't call it on the request path.
- `AgentCardValidationError` (optional `field` hint) and `AgentCardLoadError` (trigger in `Error.cause`) are distinct classes and tests distinguish them - don't collapse them.

## Build metadata

`src/agent/build-metadata.ts` mirrors `BuildAgentName`/`BuildAgentDescription`/`BuildAgentVersion` from the Go ADK's `server/metadata.go`. `BUILD_AGENT_NAME`, `BUILD_AGENT_DESCRIPTION` and `BUILD_AGENT_VERSION` are read from `process.env` once at first import and frozen into `buildMetadata`. An empty string means "not injected" and `applyBuildMetadata(card)` skips empty values, so it is safe to call unconditionally. Consumers inject at bundle time (tsup `define: { 'process.env.BUILD_AGENT_NAME': JSON.stringify('my-agent') }`) or at runtime (set the env vars before first import).

## Code Style

- `verbatimModuleSyntax` + `module: nodenext`: relative imports need `.js` extensions (`from './card.js'`) - the build fails without them.
- `noUncheckedIndexedAccess`: indexing returns `T | undefined` - use `arr[0]?.x`.
- `noPropertyAccessFromIndexSignature`: bracket notation for index signatures (`process.env['BUILD_AGENT_NAME']`).
- `exactOptionalPropertyTypes`: `{ x?: string }` rejects `{ x: undefined }`. Pass the key conditionally instead.
- `isolatedModules`: no `const enum`, and types are re-exported with `export type`.
- Unused variables are errors unless `_`-prefixed. PascalCase classes/types, camelCase functions/variables.

### Code Readability

- Write self-explanatory code: clear names and small, single-purpose functions carry the intent.
  If a block needs a comment to be understood, extract it into a well-named function or variable.
- No inline comments inside function bodies.
- Doc comments on functions and types are at most 5 lines: what it does and why, not how.
- No comments above modules, packages, or files.
- Tool directives are not comments and stay where the tool needs them (lint suppressions, build
  tags, compiler pragmas, code generation markers).
- No semicolons in documentation prose (Markdown files, doc comments): split the sentence or use
  a dash instead.

## Testing

Vitest runs in the Node environment with `globals: false` - import `describe`/`it`/`expect` from `vitest`. Prefer table-driven tests (`it.each`) for pure logic. Don't mock what runs in-process (the server can bind port 0). Coverage is informational, not gated. Tests should pass explicit `env` objects, not rely on machine state.

The `uses module-level buildMetadata` test in `tests/agent/build-metadata.test.ts` reads the live `buildMetadata` (whatever `process.env` held at module load), so its assertion is conditional. Don't "simplify" it to a hard equality.

## Commits & Releases

Conventional Commits - semantic-release (`workflow_dispatch`, `.github/workflows/release.yml` + `.releaserc.yaml`) maps `feat` to minor and most others (`fix`/`refactor`/`perf`/`docs`/`chore`/...) to patch. CI runs lint, typecheck, build, test on a Node 22/24 matrix. Required status checks for `main` are `ci (22)` and `ci (24)`.

## Security & Configuration

Never commit secrets or local env files.
