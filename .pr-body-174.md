## Summary

Adds optional Prometheus **pull** support to the OpenTelemetry telemetry provider (`createTelemetryProvider`), which was previously metrics-push-only over OTLP. Brings the TypeScript ADK toward parity with the Go ADK's pull-based Prometheus endpoint and aligns with the ADL per-signal exporter selection (`metrics.exporter.{otlp,prometheus}`).

### What changed

- New `OTEL_METRICS_EXPORTER` selector on the telemetry config: `otlp` (default), `prometheus`, `none`.
- `prometheus` wires `@opentelemetry/exporter-prometheus` (`PrometheusExporter`) as the metric reader, honoring `OTEL_EXPORTER_PROMETHEUS_HOST` (default `0.0.0.0`) and `OTEL_EXPORTER_PROMETHEUS_PORT` (default `9464`).
- `none` registers no metric reader (metrics signal off; traces/logs still export) - the ADL "omit the metrics block" case.
- OTLP push remains the default; existing env vars and behavior unchanged.
- New exports: `MetricsExporter` type, `OTEL_METRICS_EXPORTER_ENV`, `OTEL_EXPORTER_PROMETHEUS_HOST_ENV`, `OTEL_EXPORTER_PROMETHEUS_PORT_ENV`, `DEFAULT_METRICS_EXPORTER`, `DEFAULT_PROMETHEUS_HOST`, `DEFAULT_PROMETHEUS_PORT`.
- README: new "Telemetry & metrics exporters" section with the exporter-selection matrix; corrected the stale roadmap line.

This OTel Prometheus endpoint (default `9464`) is independent of the existing standalone `MetricsServer` (`prom-client`, default `9090`).

### Tests

- Config parsing for `OTEL_METRICS_EXPORTER` + Prometheus host/port (defaults, case-insensitivity, invalid/out-of-range fallback, port 0).
- Integration test that starts the provider with `prometheus`, scrapes `/metrics`, asserts a recorded counter is exposed, and that the endpoint stops after shutdown.

### Downstream impact

New env vars (`OTEL_METRICS_EXPORTER`, `OTEL_EXPORTER_PROMETHEUS_HOST/PORT`) - docs / example `.env`s / Helm values in other org repos may want updating. A `[DOCS]` ticket should track the user-facing docs update.
